For Python projects using Claude Code

A pytest Stop hook for Claude Code: two repair attempts, then an explicit unverified result.

Runs your tests after code changes, remembers verified states, and flags changed tests. Red tests send the agent back with the failure, at most 2 times. After that you see “NOT verified” instead of a quiet “done”. No signup. No reviewer model.

How the gate decides

A hook, not a prompt the agent can skip.

  1. Remembers where the session started

    At session start it records the content of your code files and the test command. Changing code counts whether you commit it or not, so committing red code doesn’t get past it.

  2. Runs only when code changed

    Docs-only edits, committed or not, and chat-only sessions never trigger a test run. Once a state is green, it isn’t retested on every message, unless a later run of it fails.

  3. Sends the agent back with the failure

    Red tests block the stop with pytest’s failure summary. If test files were edited, the agent is told not to weaken them.

  4. Stops looping, but never pretends

    After 2 fix cycles it lets the agent stop and shows “NOT verified”. A broken config or a timeout is never shown as green.

Why tests decide, not a second model

Require executable evidence, not a reviewer’s opinion.

In a July 2026 study (arXiv:2607.21656, 116 tasks), model review without running tests went both ways: Codex reviewing Claude’s code lowered the share of correct solutions, Claude reviewing Codex’s raised it. A review can help or hurt; a test run is evidence either way. So in Prove It the test suite decides. Planned for Pro: mutation checks that show whether your tests catch a broken change.

Questions

Before you install

Does it work without Codex?

Yes. Mini needs only Claude Code, Python and pytest. Mini currently integrates with Codex through AGENTS.md instructions. It does not install Codex’s native Stop hook. The rule asks Codex to run the gate’s --check before reporting done; Mini can’t enforce it.

Does it send my code anywhere?

No. Mini’s hook makes no network calls: it runs your own test command locally and writes its log to .prove-it/, which the installer adds to git’s exclude list.

What if my test suite is slow?

Tests run only after the agent changed relevant files since the session started or since the last green run. You can narrow the command, for example pytest -q -m "not slow", and set a timeout in .claude/prove-it/config.json. A timeout kills the test run’s process group.

Can the agent just weaken the tests?

The rules forbid it and the gate warns the agent whenever test files changed. The gate log records which test files changed. A determined agent can still edit a test: Prove It makes that visible, it doesn’t make it impossible.

Windows?

Via WSL. Native Windows isn’t tested.
